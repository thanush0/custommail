# Production mail server (separate from InstaBox)

## Why separate it?

InstaBox's published HTTPS application URL is not a mail domain. A public email system requires direct DNS control and reliable SMTP/IMAP reachability. Run mail services on an always-on VPS or server whose provider explicitly permits mail traffic and supplies a stable public IPv4 address with reverse-DNS/PTR control. Confirm TCP/25 inbound and outbound with the provider before paying.

## DNS

For `mail.example.net` (replace with your actual domain):
- `A mail.example.net -> MAIL_SERVER_PUBLIC_IPV4`
- `MX example.net -> mail.example.net` (priority 10)
- SPF TXT at `example.net`, e.g. `v=spf1 mx -all` only if this host is the sole sender.
- DKIM TXT record generated by your mail server at `selector._domainkey.example.net`.
- DMARC TXT at `_dmarc.example.net`, start with `v=DMARC1; p=none; rua=mailto:dmarc@example.net` and tighten after monitoring.
- PTR/reverse DNS for the mail server IP -> `mail.example.net`; set through the VPS provider.
- Ensure forward-confirmed reverse DNS: the A record for the PTR hostname resolves back to the same IP.

A free web subdomain may not permit MX records or PTR control. Check provider terms and DNS record support first. Do not use an InstaBox app URL as the MX target.

## Network

Required:
- TCP 25: inbound SMTP from other mail servers.
- TCP 587: authenticated submission with STARTTLS.
- TCP 993: IMAPS.
- TCP 80/443: ACME certificate issuance and optional webmail/admin.
Never expose unauthenticated SMTP relay. Do not expose IMAP without TLS.

## Recommended implementation

Use a maintained mail-server distribution such as docker-mailserver on the separate mail VPS. Read its current official documentation before deployment:
https://github.com/docker-mailserver/docker-mailserver

Example mailbox creation on the mail host (adapt to the currently installed release and verify its CLI syntax):
```bash
docker exec -it mailserver setup email add alice@mail.example.net
```
The command prompts for a password. Store no plaintext password in scripts or shell history. Create a mailbox for each record created in the CustomMail admin UI.

To remove or disable a mailbox, use the mail server's documented account-management command as well as the CustomMail admin UI. Preserve/backup mailbox contents before deletion.

## Connect CustomMail

Set in InstaBox `.env`:
```env
MAIL_DOMAIN=example.net
IMAP_HOST=mail.example.net
IMAP_PORT=993
SMTP_HOST=mail.example.net
SMTP_PORT=587
MAIL_TLS=true
```
The app connects from InstaBox to IMAPS/SMTP submission. If the InstaBox outbound network blocks these ports, use a private VPN/tunnel between the app and mail VPS or host the application where those connections are permitted.

## End-to-end validation

1. From an external DNS checker, verify MX, A, SPF, DKIM, DMARC and PTR.
2. From a machine outside the VPS, test TCP/25, 587 and 993 reachability.
3. Create a mailbox on the mail host and in CustomMail admin.
4. Log in to CustomMail using the mailbox address and password.
5. Send to an external mailbox you control; inspect full headers for SPF=pass, DKIM=pass and DMARC alignment.
6. Reply from the external mailbox and verify it arrives in CustomMail.
7. Test Thunderbird/phone using IMAP 993 and SMTP 587 with STARTTLS.
8. Test spam filtering, rate limits, mailbox quota enforcement, backups and restore.

## Quota note

CustomMail stores a 500 MB quota value in the application database. That value is **not enforced by Dovecot automatically**. Configure the matching per-user quota on the mail server using its supported Dovecot quota configuration, then test by uploading mail until the quota is reached. The application must not claim hard quota enforcement until that test passes.
